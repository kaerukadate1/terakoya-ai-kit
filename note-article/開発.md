# note-article を直す人へ

画面はapp/、制作指示はprompts/、スキルはskills/、テストはtests/で編集します。release-map.jsonがreleases/note-article-v1/への生成先を定義します。配布先は直接編集しません。

```sh
node scripts/generate-tool-release.cjs note-article --write
node releases/note-article-v1/scripts/build-manifest.cjs
cp releases/note-article-v1/MANIFEST.json note-article/release/MANIFEST.json
node scripts/generate-tool-release.cjs note-article --check
node --test releases/note-article-v1/tests/*.test.cjs
node releases/note-article-v1/scripts/verify-release.cjs
node scripts/verify-entrypoints.cjs
```

既存タグを付け替えず、新しい固定版を作ります。開始文・kit.js・extensions.jsのスキルURLは同じ新タグにそろえます。ファイルを増やす場合は生成表とMANIFESTの検査対象にも含めます。

配布ファイルにSite IDや本人の記事・設定・返送結果を加えません。meta[name="site-project-id"]は空のテンプレートです。新規構築時に、その実行で作成した本人のproject_idを設定します。

旧データの読み込み形式と相対パスを保ちます。既存Siteを更新する場合、記事ストックやreturnsを空テンプレートで上書きしないでください。本人のWorkでの実生成と保存・返送は、単体テストとは分けて確認します。
