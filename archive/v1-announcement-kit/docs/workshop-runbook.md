# 初回ワークショップ進行案（2時間）

運営向けの進行案です。2026年9月13日の運営者（ChatGPT Pro）実測をもとに組んでいます。参加者本人のアカウント・想定プランでの通し検証は未実施のため、各工程の時間は実測値＋余裕で読んでください。正式な日時・料金・申込導線は確定後に案内へ反映します。

## 持ち帰り物（完了条件）

- 自分のマイツール（本人限定サイト）1つ
- マイツールに登録された使えるAIツール 少なくとも1つ（初回はセミナーまるっと用意くん）
- 告知文・LP・画像は当日の到達範囲に応じて、完成物または続きの手順を持ち帰る

## 参加者の事前準備

- ChatGPTアカウントを作成しログインできること。Sitesでのサイト作成が使えるプランであること（想定プランの確定は運営の残件）。
- 事業名と事業内容を1〜3文で書いたメモを用意しておくこと（制作中の質問にそのまま答える）。
- セミナーまるっと用意くんを試す場合は、架空でもよいのでセミナーの題材を決めておくこと。

## 運営の事前準備

- 開始文の配布方法を決める：[マイツール開始文](../prompts/01-start-mytools.txt)と[ツール開始文](../prompts/03-start-seminar.txt)を、オープンチャット・印刷・画面共有のいずれかで全員がコピーできる状態にする。GitHub操作は参加者に求めない。
- 適用版を固定する：検証済みのコミットまたはタグへの固定URLを開始文へ使う。直近の再検証適用版は `71032999fe86189cb31020caae4c7a7e48f3995c`。
- 運営告知を更新する：開催が正式なら[announcements.json](../announcements.json)の本文・期間・リンクを当日用に差し替える。反映に数分かかる場合があるため開催前に済ませる。
- 記録用に[検証チェックリスト](verification.md)と下記の記録表を用意する。
- フォロー役の分担を決める：画面を見て回る人、詰まった人の個別対応をする人。
- 推奨モデルを案内に含める：2026-09-22のテスト会では「高」モデルでツール構築に約40分、「中程度」で約5分と大差が出た。当日は「中程度」以下を推奨し、性能低下中のAstraは避ける案内をする。

## 時間が足りないときの縮退順

1. 必須：マイツール作成・保存＋セミナーまるっと用意くんの登録（ここまでで「自分の仕事場と使えるツール1つ」を持ち帰れる）。
2. 次点：告知文を1媒体だけ生成・保存（「すべて作る」は8媒体で待ちが増えるため、時間が厳しい場合は1媒体に限定）。
3. 後回し可：LP・画像は運営の実演画面を見せ、「ChatGPTで開く」の操作と保存手順だけを各自確認して持ち帰り課題にする。生成結果を見せるだけで参加者の完成扱いにしない。
4. 制作待ちが長い場合：待ち時間に左下の運営告知や登録済みツールの説明を入れ、空白時間を作らない。

## よくあるつまずきと戻り先

| 症状 | 戻り先 |
| --- | --- |
| 質問が出ない・制作が進まない | 開始文の再送。それでも進まなければ完全版の貼り付け（READMEの手順2） |
| 「アクセス権がありません」 | サイト作成時と同じChatGPTアカウントでログインしているか確認 |
| ツールが消える・登録できない | URLが実在するか・重複していないか確認後、再登録して再読込 |
| JSONを取り込めない | コードブロック全体をコピー。依頼IDは書き換えず、対応する返答を取り直す |
| 運営告知が出ない | 配信待ち（数分）の場合あり。ツール本体の操作は継続できる |
| サイト作成が始まらない | プラン・ログイン状態を確認。参加者条件の問題として記録し、宿題扱いにしないで代替を案内 |

## 当日の記録フォーマット

参加者ごと、または工程ごとに以下を残します。実測が本番データになります。

- 参加者のプラン・端末（PC/スマートフォン）
- 各工程の開始・終了時刻と待ち時間
- つまずいた箇所と戻り先、解決に要した時間
- 2時間で終わった範囲・残った範囲
- 「自分の仕事場＋ツール1つ」を持ち帰れた人数

結果は[実測結果](validation-results.md)へ追記し、実施日・対象版・参加者条件を分けて記録します。
