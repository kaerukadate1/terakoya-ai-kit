# 生成指示の仕様

セミナーまるっと用意くんが「ChatGPTで開く」（`https://chatgpt.com/?q=`）で渡す依頼文の仕様です。どのサイトが作られても同じ品質の依頼文が出るよう、ここで定義します。

## 依頼文の構造

依頼文は次の順で組み立てます。

1. 依頼ヘッダ（依頼IDと目的）
2. 事業プロフィール
3. 告知素材
4. 共通ルール（創作禁止・文体・避けたい表現）
5. 媒体別ブロック（選択した媒体だけを連結）
6. 返却形式（JSON）
7. セルフチェック指示

## 依頼文テンプレート

`{{ }}` はツールが差し込む項目です。

```
あなたは中小企業・個人事業主向けの告知文を作るライターです。
依頼ID: {{requestId}}

【事業プロフィール】
{{事業プロフィール全文}}

【告知素材】
{{告知素材全文}}

【一番伝えたいこと】
{{素材から読み取れる告知の芯を1行で。明示があればそれを使う}}

【共通ルール】
- 「未定」と記載した項目は、日時・料金・定員・会場・申込先を含め創作しないでください。未定のまま書くか、その旨を示してください。
- 実績・数字・お客様の声・資格など、素材にない情報を追加しないでください。
- 「絶対に満席になります」「必ず成果が出ます」などの断定・誇大表現は使わないでください。
- 不安をあおって追い立てる書き方はせず、読者の不安を「次の一歩」へつなぐ書き方にしてください。
- 「本質は」「これからの時代は」「課題解決」「価値提供」「DX」など、教祖調・営業調の決まり文句は使わないでください。
- 冒頭は抽象的な宣言ではなく、具体物・数字・読者の状況から入ってください。説教や教訓で締めないでください。
- 同じ書き出し・同じ文末の型を3回以上繰り返さないでください。一文は一義にし、長文で詰め込まないでください。
- 事業主本人がお客様へ語りかける声で書いてください。外側の制作業者が宣伝している文調にしないでください。
- どの媒体でも【一番伝えたいこと】の芯を外さないでください。
- 文体は【事業プロフィール】の「希望する文体」に従ってください。指定がなければ、です・ます調で簡潔に。
- 「避けたい表現」に挙げた言葉・表現は使わないでください。
{{デモ素材の場合: これはデモ素材です。すべての出力に読み手がデモと分かる表記を入れてください。}}

【作ってほしいもの】
{{選択した媒体のブロックを列挙}}

【返却形式】
次のJSONをコードブロックで返してください。
{"requestId":"{{requestId}}","results":[{"id":"媒体ID","text":"本文","warnings":["注意点"]}]}
- requestIdは上記の依頼IDをそのまま使ってください。
- resultsには依頼した媒体だけを含めてください。
- warningsには、後述のセルフチェックで見つかった注意点を入れてください。なければ空配列 [] です。

【返却後の案内】
返答の末尾（JSONのコードブロックの直後）に、利用者への次の一手を必ず1行で添えてください：「このJSONをコピーして、セミナーまるっと用意くんの『結果の取り込み』欄に貼り付け、確認画面で『取り込む』を押してください」

【セルフチェック】
返す前に各結果について確認し、問題があればwarningsに書いてください。
1. 未定項目や素材にない情報を創作していないか
2. 媒体ごとの必須要素がすべて入っているか
3. 文字数の目安を大きく超えていないか
4. 避けたい表現・誇大表現を含んでいないか
5. 日付・金額・URLの表記に誤りがないか
```

## 媒体別ブロック

依頼文の「作ってほしいもの」には、選択した媒体のブロックだけを次から連結します。

### copy（汎用告知文）

```
- id: copy　汎用告知文。400〜600字を目安に、「何を・誰に・いつ・どこで・いくら・どう申し込むか」をすべて含めてください。チラシや口頭案内に転用できる素直な文章にしてください。
```

### email（メール案内）

```
- id: email　メール案内。次を含めてください。
  ・件名（30字以内、開く理由が分かるもの）を本文の1行目に「件名：」付きで
  ・本文冒頭で結論（何の案内か）を伝える
  ・申込方法・URLを本文内で1箇所、明確に示す
  ・末尾に署名欄（事業名）を置く
  目安：本文600字以内。
```

### flyer（チラシ文言）

```
- id: flyer　チラシに載せる文言。次の階層で出力してください。
  ・大見出し：セミナー名（15字以内目安）
  ・サブ見出し：参加すると得られること（20字以内目安）
  ・情報ブロック：日時・会場・料金・定員・申込方法を箇条書き
  ・一言CTA：申込を促す1文（20字以内目安）
  文字を詰め込みすぎないでください。
```

### lp（告知LP原稿）

```
- id: lp　告知LPの原稿。次のセクション構成で出力してください。各セクションは「## セクション名」で始めてください。
  1. キャッチコピー（誰向けか・何が得られるかが一目で分かる。約束は1つに絞る）
  2. こんな方へ（対象者の悩み・状況を3点。責める書き方にしない）
  3. 得られること（3点、具体的に）
  4. セミナー内容（扱うこと・進め方）
  5. 講師紹介（事業プロフィールにある範囲で。経歴の創作は禁止）
  6. 開催情報（日時・会場・料金・定員・申込方法を表形式。各項目は素材の文字列どおり正確に）
  7. 申込CTA（ボタンに載せる文言と申込先）
  8. FAQ（想定される質問と回答を3問）
  密度のルール：文字を小さくして詰め込まないでください。情報が多い部分は項目を減らすか分けてください。1セクションで主役にする数字・要素は1つまで。CTAは序盤と末尾の2箇所にしてください。
```

### x（X投稿文）

```
- id: x　X（Twitter）投稿文。140字以内。冒頭1行で関心を引き、日時と申込先（またはLP案内）を含めてください。ハッシュタグは使う場合も2個まで。
```

### instagram（Instagramキャプション）

```
- id: instagram　Instagramキャプション。読みやすく改行を入れた本文（目安300字以内）と、関連ハッシュタグを5〜10個つけてください。絵文字はプロフィールの文体に合わせ、指定がなければ控えめに。
```

### line（LINE配信文）

```
- id: line　LINE一斉配信の文面。目安200字以内。改行を効かせ、要点→日時→申込URLの順に。近しい相手へ送る文体にし、押しつけがましい表現は避けてください。
```

### checklist（公開前チェックリスト）

```
- id: checklist　この告知を公開する前に確認すべき項目のチェックリスト。日時・料金・申込導線・リンク・誤字脱字・画像との整合について、10項目以内の箇条書きで出力してください。各項目は「〜を確認した」でチェックできる文にしてください。
```

## ツール側の組み立て要件

- 事業プロフィールの項目は次のように使い分けます：事業名・事業・サービス内容は本文の根拠に、強みは訴求軸に、料金・提供形式は参考情報に、希望する文体はトーン指定に、避けたい表現は禁止語として明示します。
- 「一番伝えたいこと」は、素材の「文体・必ず伝えたいこと」に明示があればそれを使い、なければ素材の内容から1行に要約して差し込みます。素材にない新しい主張は作りません。
- 素材の「未定」項目は依頼文でも「未定」と明記し、創作禁止ルールへ含めます。
- デモ素材で依頼する場合は、依頼文へデモ表記の指示を入れます。
- 選択した媒体だけのブロックを連結します。未選択の媒体を依頼文に含めません。
- 依頼IDは依頼文の冒頭と返却形式の両方に入れ、返却JSONとの照合に使います。
- 依頼文には返却JSONをツールへ貼り戻す手順（【返却後の案内】）まで含め、利用者が追加説明なしに「開く→送信→JSONを貼る→取り込む」を往復できる状態にします。
- 「ChatGPTで開く」ボタンは、組み立てた依頼文をURLエンコードして `https://chatgpt.com/?q=` に結合したリンクを新しいタブで開きます。「依頼文をコピー」などのコピー専用ボタンは置きません。
- エンコード後のURLが8,000文字を超える場合は、選択媒体を分割した同じrequestIdの部分依頼を自動で組み立て、「依頼を送る（1/2）」「（2/2）」のように順に開くボタンを出します。各部分の返却は部分取り込みで同じ依領へ統合されます。

## 返却JSON（バージョン2）

```json
{"requestId":"r-2026xxxx-001","results":[{"id":"email","text":"件名：…\n\n本文…","warnings":["開催日時が未定のままです"]}]}
```

- `requestId`：依頼文の依頼IDと一致必須
- `results[].id`：依頼した媒体IDのみ。重複・未依頼は拒否
- `results[].text`：本文（文字列）
- `results[].warnings`：文字列の配列。セルフチェックで見つかった注意点。なければ空配列

`text` だけを持つ旧形式の返却も受け付けますが、依頼は常にこの形式で出します。取り込み確認画面では text と warnings を併記します。

## やり直し（部分再依頼）

特定の媒体だけ書き直したい場合、ツールは同じ依頼IDで対象媒体だけを含む再依頼文を作ります。形式は同じで、「作ってほしいもの」に直す媒体のブロックと修正指示だけを入れます。

```
【修正指示】
id: email の結果を次の観点で書き直してください：{{修正したい観点}}
```

修正したい観点の例：「冒頭のフックを具体的な数字から始めて」「切り口を体験談調から問題提起調に変えて」「押しつけがましさを下げて」「文字数を半分に」。

返ってきたJSONは通常どおり検証・確認し、取り込むと該当媒体の結果だけが更新されます。ほかの媒体の結果は保持します。
