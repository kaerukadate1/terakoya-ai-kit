# 共通告知の仕様

## データ

公開JSONのルートは `schemaVersion: 1` と `announcements` 配列です。配信URLは運営が公開後に実在を確認して設定します。想定はリポジトリの `announcements.json` を指すraw URLです。GitHubのHTML表示URLをJSONとして読み込まないでください。

| キー | 型 | 意味 |
| --- | --- | --- |
| id | string | 更新しても維持する一意のID |
| title | string | 短い告知タイトル |
| body | string | 要点。HTMLとして実行しない |
| startsAt | string | 必須。表示開始。タイムゾーン付きISO 8601 |
| endsAt | string | 必須。表示終了。タイムゾーン付きISO 8601 |
| detailUrl | string | 必須。告知詳細へのHTTPSリンク |
| snsUrl | string | 関連SNS投稿へのHTTPSリンク。未設定は空文字。nullは不可 |
| isDemo | boolean | trueなら必ず「デモ」と表示 |
| priority | number | 必須。大きいものを先に表示 |

開始前・終了時刻以後の告知は表示しません。期間や型の不正な行は除外し、未知のschemaVersionは表示しません。URLはHTTPSを検証します。未確定の申込先やSNS投稿を実在するリンクとして作らないでください。詳細ページが未準備の告知は配信せず、SNS投稿が未公開の場合はsnsUrlを空文字にします。

## 表示

PCでは左側ナビゲーションの下部に告知カードを置きます。モバイルでは本文の後ろに置き、固定表示でフォームを隠さないようにします。タイトル、本文、「詳しく見る」「SNSを見る」を表示し、リンクがないボタンは出しません。外部リンクは新しいタブで開きます。

優先度順に最新の対象告知を表示します。同優先度は開始時刻の新しい順で並べます。正常な取得結果が空配列なら告知枠を消します。読込失敗やオフラインでは、前回取得した告知のうち表示期間内のものだけを保持し、更新できていない旨を表示します。期限は現在時刻で判定し、プロフィール保存・ツール起動を妨げません。

## 更新と検証

JSON更新 → 公開URLを再取得 → 2つのサイトで告知を再取得 → サイトを再生成せず内容が変わったことを確認、の順で検証します。キャッシュの反映待ちを即時更新と呼ばないでください。初回表示時、以後1分ごと、ウィンドウへフォーカスが戻ったときに再取得します。

実在する告知・SNS投稿を使うときは両方の公開URLを確認します。検証用はisDemo=trueとし、開催決定済みのイベントに見える表現を避けます。個人データ、内部チャット、秘密情報を配信JSONへ入れません。

## サイト経由の取得と再利用部品

ブラウザからGitHubへ直接アクセスできない環境を考慮し、同じサイトの `/api/announcements` を経由します。サーバーは固定した公開ファイルだけを取得し、任意URLの中継には使いません。個人情報や認証情報をGitHubへ送りません。

- [検証・選択処理](../templates/announcements.ts) を lib/announcements.ts へ配置
- [表示部品](../templates/announcement-card.tsx) を components/announcement-card.tsx へ配置
- [取得API](../templates/announcement-route.ts) を app/api/announcements/route.ts へ配置

外観は利用先のCSSへ合わせます。1分は更新確認間隔であり、通信状態や配信元の制限で反映が遅れる場合があります。参加者が増えたら、各サイトからGitHubの公開ファイルを個別取得する方式を共通キャッシュ配信へ移行します。

サイト内の取得は同一オリジンの認証Cookieを伴う通常のfetchを使います（credentials: same-origin）。省略すると本人限定Sitesでは認証が失われます。GitHubへのサーバー側取得にCookieは転送しません。
