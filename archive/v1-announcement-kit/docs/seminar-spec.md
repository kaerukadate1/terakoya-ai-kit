# セミナーまるっと用意くん

## 目的と画面

告知素材を一度入力し、ChatGPTで文章・LP・画像を作るための指示と結果をまとめる本人専用ツールです。「告知を作る」「事業情報」「履歴」「設定」の4画面を基本にします。名称はセミナーまるっと用意くんに統一します。

初版のサイト内部から生成AI APIを呼びません。APIキー入力、SNS自動投稿、決済、CRMを追加しません。文章を保存した状態と、LPや画像が完成した状態を区別します。

## 入力と保存

告知素材は100KB以下のtxt、貼り付け、直接入力を受け付けます。直接入力は「何を告知したいですか」必須、「詳しい情報」「文体・必ず伝えたいこと」任意。各項目の入力欄の近くに、入力の質を上げるための良い例・悪い例を短く表示します（例：詳しい情報なら「日時・会場・料金・対象者・得られることが分かれて書かれている」が良い例、「がんばりますので来てください」のような情報のない文が悪い例）。事業情報はマイツールからコピーして保存します。コピー形式は「【事業名】と次行の値」「事業名：値」の両方を受け付け、元の番号付きシートも維持します。[取り込み処理の参考](../templates/profile-parser.ts)を利用できます。初期状態に架空の本人情報を入れません。

直接入力の各欄は空で開始し、初期値・プレースホルダ・選択式プリセットに架空の告知例や「テスト用」の文字列を入れません。「テスト入力」「サンプルを入れる」「デモで試す」などのボタン・リンク・切替は入力画面に置きません。良い例・悪い例は説明文としてのみ表示し、入力値や選択肢へ流用しません。

日時、価格、定員、会場、申込URLが未定なら未定として保持し、生成依頼に創作禁止を含めます。架空素材で試す場合はデモ表示を継続し、完成物にも表示します。

入力に迷う場合の補助として、材料欄に「ChatGPTに相談する」ボタンを置きます。押すと相談文を `https://chatgpt.com/?q=` に入れて新しいタブで開き、利用者のChatGPTが本人の過去のやり取りや記憶を最大限活用し、実際の告知にそのまま使えるレベルでシート各項目を作成する流れを案内します。相談文には、埋められる項目は全部埋める・どうしても分からない項目だけ空欄にする・推測で数字・日時・実績・固有名詞を作らない・シートと同じ形式のテキストだけを返す指示と、空のシート雛形を含めます。入力済みの事業情報は既知の情報として添えます。返ってきた回答は貼り付けまたはtxt読み込みでツールに戻し、本人が確認・修正してから反映します。相談結果を自動で確定入力にしません。相談文の文言は[相談文テンプレート](../prompts/06-consult-material.txt)を使い、サイトごとに独自の文面を作りません。

プロフィール、素材、選択媒体、依頼、取り込んだ結果、完成物リンクを永続保存します。再読み込みで消えず、保存失敗時は入力を保持します。本人を信頼できる識別子で固定し、画面とAPIの双方で本人確認します。

## ChatGPTへの依頼と結果

媒体IDは `copy`, `flyer`, `lp`, `x`, `instagram`, `line`, `email`, `checklist` の8つです。選択した媒体だけを依頼します。依頼ごとに新しいrequestIdを発行し、素材の版と対応付けます。

ツールが出力する依頼文は、[生成指示の仕様](generation-spec.md)のテンプレートと媒体別ブロックに従って組み立てます。プロフィール項目の使い分け、未定項目・デモ素材の扱い、返却形式も同仕様に従います。サイトごとに独自の依頼文を作りません。

1. 素材と媒体を保存する。
2. 「ChatGPTで開く」ボタンを押す。ツールは依頼文をURLエンコードして `https://chatgpt.com/?q=` に結合したリンクを新しいタブで開き、依頼文が入力済みの状態でChatGPTを起動する。利用者は開いたチャットでそのまま送信する。「依頼文をコピー」などのコピー専用ボタンは画面に置かない。
3. 依頼文が長くURLに収まらない場合（エンコード後の合計が8,000文字を超える目安）は、ツールが選択媒体を自動で分割し、同じrequestIdの部分依頼として「依頼を送る（1/2）」「（2/2）」のように順に開くボタンを出す。各部分の返却JSONは部分取り込みで同じ依領へ統合される。
4. ChatGPTが返したJSONを「結果の取り込み」欄に貼り付ける。この欄は「ChatGPTで開く」ボタンと同じ画面内に置き、「開く→送信→JSONを貼る→取り込む」の往復が1画面で完結するようにする。返却の貼り戻し手順は依頼文の【返却後の案内】にも必ず含める。
5. 取り込み前の確認画面で本文とwarnings（自己点検の注意点）を確認する。
6. 明示的に「取り込む」を押して保存する。

すべてのボタンは、押した直後に結果が分かる表示（「コピーしました」「保存しました」、状態の変化など）を返します。押しても反応しないボタンや、現在の操作で使わないボタン（下準備用・テスト用など）は画面に置きません。認証の未確認や必須入力の不足でボタンを無効にする場合は、無効の理由と次の操作（例：ChatGPTにログインして開き直す・必須欄を入力する）をボタンの近くに表示します。理由が分からないまま押せない状態にしません。

返却形式の例（example-requestは実際の依頼IDに置換）:

```json
{"requestId":"example-request","results":[{"id":"email","text":"ここに告知文","warnings":["開催日時が未定です"]}]}
```

requestId不一致、依頼していない媒体、重複媒体、不正な型、古い素材への返却を検証します。欠けた媒体がある場合は受領分と未受領分を示し、一括完了にしません。文章内のHTMLを実行しません。素材を変更したら既存結果を「更新前の内容」と表示します。

一部の媒体だけ書き直したい場合は、同じrequestIdで対象媒体のみを含む再依領文を生成できるようにします（[生成指示の仕様](generation-spec.md)の「やり直し」）。部分返却を取り込むと該当媒体だけが更新され、ほかの結果は保持します。

## LP・画像への接続

lpの文章から[制作手順](production-flow.md)に沿って実際の告知LPを作ります。flyerとinstagram等の文章から実際の画像を作ります。ツールは原稿と完成URLの関連を保持します。チラシ・SNS画像はPNG・JPEG・WebP、10MB以下を本人用ストレージへアップロードできます。アップロードした画像は本人用であり、一般公開URLとは区別します。原稿を変更したら完成物が変更前の原稿によるものと表示します。

LPの利用URL、チラシ画像、SNS画像を結果と関連付けます。未作成の成果物に架空URLを入れません。完成判定にはLPの表示と申込導線、画像の文字・寸法・表示を含めます。投稿文の完成とSNSへの投稿完了も分けます。

lp結果の原稿と[LP作成の指示](../prompts/04-create-lp.txt)、画像用原稿と[画像作成の指示](../prompts/05-create-images.txt)を結合した依頼文についても同じ「ChatGPTで開く」ボタンを用意します。各指示書の末尾にある「次の一手」の行まで依頼文に含め、返ってきたURLやファイルをツールへ関連付ける手順が利用者へ伝わるようにします。URLに収まらない場合は、依頼履歴に保存した依頼文の全文を表示し、手動で写して貼り付ける案内を出します。

## 履歴と複数告知

告知は複数件保存でき、「履歴」画面で一覧します。各告知についてセミナー名、更新日時、進捗（素材入力→原稿取り込み→LP→画像の到達状況）を表示します。

告知ごとに依頼履歴（requestId・選択媒体・発行日時・返却の有無・依頼文の全文）を保持し、どの依頼が未返却かを一覧で追跡できるようにします。返却が複数回に分かれた場合も、依頼単位で受領状況を示します。

「履歴」画面への導線は「告知を作る」画面から常時1操作でたどれる位置に置きます。履歴の告知を開くと、その告知の素材・依頼文・取り込んだ原稿・完成URL・画像をいつでも再参照できます。過去の告知を直接編集はせず、「複製して編集」で新しい告知として引き継ぎます。

## 公開前チェック

「公開前チェック」画面を用意し、完成物を公開へ出す前の状態を一覧で示します。

- 日時・料金・定員・会場・申込先が「未定」のまま残っている項目を明示する
- 未対応のwarningsがある媒体を示す
- デモ素材由来の原稿・LP・画像にデモ表記が残っているかを示す
- 完成URL・完成ファイルが未関連付けの成果物を示す
- checklist媒体の結果がある場合はその内容を表示する

この画面は公開操作ではなく確認用です。投稿や公開は本人が別途行います。

## 完了とやり直し

「新しい告知を作る」は現在の告知を履歴へ保存してから新規を開始します（内容を消さず自動で保存します）。事業情報はすべての告知で共通に保持します。入力・保存・JSON確認・反映・再読込・完成物参照・履歴参照・公開前チェックを通して確認します。
