# 共通設計

## 役割

| 要素 | 役割 | 保存するもの |
| --- | --- | --- |
| 公開GitHub | AIが読む共通仕様と運営告知 | 汎用仕様、公開告知、架空の検証素材 |
| マイツール | 本人の仕事の入口 | 事業プロフィール、登録ツール、デザイン |
| セミナーまるっと用意くん | 告知制作の入力と結果管理 | 告知素材、依頼ID、返却文章、完成物リンク |
| ChatGPTのワーク | 指示を読み、文章・サイト・画像を制作 | 利用者が渡した制作対象 |
| 公開告知LP | お客様への案内 | 公開してよい告知内容と申込先 |

事業情報はマイツールでコピーしてツールへ貼り付けます。初版で自動同期を前提にしません。ツールはChatGPTへの依頼を組み立て、文章の返却をJSONで照合します。画像そのものをJSON本文へ詰め込みません。

## 制作中の会話

共通部分の作成開始 → 事業名の質問 → 同じサイトへ反映 → 事業内容の質問 → 同じサイトを確認・保存、の順です。会話で最初から分かっている項目は省略します。途中回答を受け取れるかは利用するワーク環境で実測し、応答待ちで停止した場合はその状態を記録します。

## 公開範囲

参加者の編集用サイトは本人専用を標準とします。運営の公開デモには架空情報だけを使い、本人専用の実証と区別します。公開GitHub、運営告知、公開LPから本人のメモや非公開ツール情報へアクセスできないようにします。

## 更新

共通仕様は検証済みの版を固定して制作に使います。告知は公開JSONの読み込みで更新します。サイト機能を変える更新は、対象サイトの修正・検証・保存が必要です。
