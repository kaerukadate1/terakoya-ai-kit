# 寺子屋AI マイサイト v5 | ビルドプロンプト

この文書は、短い「スタータープロンプト」から読み込む本体の制作指示です。参加者本人のChatGPT Work / Sitesなど、本人限定サイトを作成・更新できる環境で使用します。公開LPではありません。必要な機能が利用できない場合は、作れたことにせず未完了として報告します。

## 目的

本人の仕事で使うものを一か所に集めた「寺子屋AI マイサイト」を作ります。従来のWebツールURLに加えて、ローカルのファイル・バッチ、スキル、プロンプト、その他の参照情報を登録し、種類で絞り込めるようにします。ブラウザはローカルのバッチやスキルを直接実行・インストールできません。対象の場所や本文を保存・コピーするだけです。

## 読む順番と固定版

1. この文書と同じ `releases/mytools-v5/` の `README.md`、`index.html`、`styles.css`、`app.js`、`assets/terakoya-logo.jpg` と、`plugins/terakoya-ai-creative/skills/terakoya-web-design/SKILL.md` を実際に取得してください。ChatGPT Work / Sitesで制作する場合は同スキルの `references/work-sites-guidance.md` も読みます。取得できなければ読んだふりをせず、どのファイルが読めなかったか報告してください。
2. 同フォルダの画面と登録動作を基準にします。デザインスキルは読みやすさ・操作・検証に適用し、採用済みのHTML/CSS/JSを一から再設計しません。必要なサーバー側の本人認証・永続保存だけ接続します。見た目はv4のロゴ、紺と金、明朝見出しを引き継ぎます。
3. 次回講座は公式サイトの `https://terakoya-ai.vercel.app/api/next-workshop` から取得します。取得する公開項目はタイトル・内容・開催日時です。運営が反映した公開データだけを表示し、未公開・取得失敗なら古い講座情報を代わりに出しません。任意URLを代理取得するAPIは作りません。旧 `announcements.json` のデモは表示しません。

参照元リポジトリ: `https://github.com/kaerukadate1/terakoya-ai-kit`。制作時はスタータープロンプトが指す同じコミット・タグ・ブランチのファイルをそろえて使用してください。GitHub上のファイルを取得できない場合、ファイルの中身を推測で再現しないでください。

## 登録仕様

登録項目は `id / type / target / name / description / memo / guideUrl / icon`。`type` は次の5種類です。

| 種類 | `target`に保存するもの | 一覧での主操作 |
| --- | --- | --- |
| `web` | `http`/`https` のURL | 別タブで開く |
| `local` | 手元のファイル・フォルダ・バッチの場所 | 場所をコピー。実行しない |
| `skill` | GitHub等のURL、または手元のスキルの場所 | 安全なWeb URLだけ開く。それ以外はコピー。インストールしない |
| `prompt` | プロンプト本文 | 本文をコピー。自動実行しない |
| `other` | その他の参照先や識別子 | 内容をコピー。自動実行しない |

- 種類選択に応じて入力名と説明を変え、必須の名称と参照先/本文を検証します。Web URLと説明ページURLには `http`/`https` 以外を使わせません。保存済みデータも開く前に同じ検証をします。
- `skill` は登録と参照だけです。スキルの内容をサイト内で実行したり、GitHubのコードを自動でインストールしたりしません。
- `local` はパスのメモです。ブラウザで `.bat`、`.cmd`、`.ps1`、`file://` を直接起動する設計にしません。実行が必要なら利用者がローカル環境で確認して行います。
- 種類ごとの絞り込み、追加、編集、並べ替え、一覧からの解除、再読込後の保持が必要です。解除は登録情報だけを外し、実ファイルや元ツールを削除しません。
- 旧v4の `{url,name,...}` 登録は `type:web`、`target:url` として読み込み、消さずに移行します。既存の事業プロフィール、ツール順序、アイコン、ロゴ、サイト名、配色も保持します。移行前の保存データを復元可能にしてから切り替えてください。

## 本人限定と保存

- 新規作成では本人だけが閲覧・編集できるサイトを作ります。既存の本人サイトを更新する場合は、その所有者を確認し、既存データを失わない更新手順を選びます。別人のサイトや保存領域を上書きしません。
- 本番はWork側のサーバー認証と永続保存を使用します。ローカル版の `localStorage` は画面・操作の見本であり、本番保存ではありません。画面、データ取得・更新、画像取得の全経路で同一の本人確認を行います。最初の訪問者やログイン中の全員を所有者とみなしません。
- プロンプト本文、ローカルパス、個人の事業情報をGitHub、共通告知、公開ページへ書き込みません。登録したURLへサイトから勝手に通信したり、ローカルのコマンドを実行したりしません。
- 保存対象は、事業プロフィール、登録項目と順序、アイコン、個人ロゴ、サイト名、テーマと配色です。保存失敗時は成功表示をしません。

## 完成確認

デスクトップ幅と390px幅で表示し、以下を実際に確認してください。

1. 旧v4のURL登録が残り、Webとして開ける。
2. 5種類すべてを登録・編集・絞り込みでき、再読込後も残る。
3. WebとURL型スキルだけが安全な外部リンクになり、バッチやプロンプトはコピーのみ。`javascript:` 等は開かない。
4. 登録解除で元ファイル・元ツールは削除されない。プロフィール、ロゴ、配色も保持される。
5. 本人以外は画面・データ・画像にアクセスできない。告知のデモ・期限切れは表示されない。

確認できない項目は `未確認` と明記します。サイトURL、使用した版/参照コミット、既存データ移行結果、本人限定と保存の確認結果、未完了点を短く返してください。ZIPやコードだけを渡して完成としないでください。参加者へGit操作、APIキー、手動デプロイを求めないでください。
