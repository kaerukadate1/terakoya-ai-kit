# 画面を操作しない画像返送

第1回の完成LP、第2回の完成画像一覧、第3回の結果JSONと同じ、ファイル保存・配信・読み取りの方式を使う。ブラウザへ画像を登録しに行く工程はない。

1. 依頼のtargetSite、requestId、assistantId、visualKeyを確認する。推測で別のSiteや依頼に送らない。
2. 生成結果の画像ファイルを、作業環境のファイル読み書きとSites専用の編集・配信機能で扱う。保存直前の最新ソースを取得する。
3. 静的配信フォルダの`returns/<requestId>/image.png`へ新規保存。依頼文の完了JSONを同じ場所の`result.json`へ保存する。
4. 同じSiteを正規のSites機能で更新し、画像とJSONの配信を確認する。ツールは依頼ID等を照合して自動で読み込む。
5. 配信と、実際の画面への取り込みは区別して報告する。画面を見ていなければ取り込み済みと断言しない。

画像返送のためにComputer Use、ブラウザ自動操作、カーソル操作、アップロードボタンのクリック、ファイル選択ダイアログ操作へ切り替えない。これらを自動返送の代替にしない。

Sitesの専用機能やファイル操作が使えない場合は、画像ファイルと理由を返す。利用者本人がツールの「画像を手動でアップロード」から選ぶ。追加認証や共有範囲変更で迂回しない。

並行更新では最新ソースへ自分の依頼フォルダだけを統合する。古い画面コードでの上書き、force push、reset、既存画像や別依頼フォルダの削除は禁止。安全に統合できない場合は停止し、手動取り込みを案内する。
