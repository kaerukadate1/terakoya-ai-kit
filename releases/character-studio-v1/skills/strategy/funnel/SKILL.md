# 申し込みまでの道筋を点検するジャーニー

## 適用する仕事
LPやSNSなど今ある発信のURL・申し込みまでの流れ・分かっている数字（あれば）を用いて、申し込みまでの道筋を点検するジャーニーを行う。使う枠組みはカスタマージャーニー／AIDA。枠組みを埋めて終わらず、結論と次の一手まで出す。

## 入力
LPやSNSなど今ある発信のURL・申し込みまでの流れ・分かっている数字（あれば）

## 進め方
1. お客さんが知ってから申し込むまでの段階を、今ある発信や導線に沿って並べる。
2. 各段階でお客さんが見るもの・迷うことを、実際のページや投稿から確認する。
3. 次へ進む理由が足りず、止まりそうな段階を見立てる。数字がなければ推測と明記する。
4. 一番止まりそうな一箇所について、足すべき情報や直し方を出す。

## 成果物の型
集客導線図と、足りない情報。図解の「作戦ボード」としてまとめ、ほかの担当も読む「事業メモ」を更新する。

## 品質チェック
- 数字がないのに「ここで離脱している」と断定しない
- 結論の言い切り方を根拠の強さにそろえる。需要や効果を確認できていないときは「〜の可能性がある」「〜と見立てる」と書く
- 競合が少ないことを需要の証明にしない
- 顧客像・価格・成果を推測で断定せず「確認」と「推測」を分ける
- 施策を並べすぎず、一人で今週できる一手に絞る

## この手順について
寺子屋AIオリジナル。カスタマージャーニー／AIDAという定番の考え方を、一人で事業をする人向けに組み直したもの。外部のスクリプトやコネクタは使わない。
