# 寺子屋AI マイサイト v4 | Work 制作指示

この指示は参加者本人の ChatGPT Work で実行する。目的は、寺子屋AIの見た目を備えた本人専用の「マイサイト」を1つ完成させること。公開LPではない。旧 `prompts/01-start-mytools.txt`、`02-mytools-full.txt` の機能要件と `docs/announcements.md` の告知仕様を引き継ぐ。見た目と画面構成はこの固定版を正とする。

固定版: `https://github.com/kaerukadate1/terakoya-ai-kit/tree/mytools-v4.0.0/releases/mytools-v4`

## まず実行すること

1. 同フォルダの `index.html`、`styles.css`、`app.js`、`assets/terakoya-logo.jpg` を取得する。4ファイルの相対パスを保ち、HTML/CSS/JS を作り直さず使う。`README.md` でローカル版と本番版の差を確認する。デザイン確認には同じキットの `plugins/terakoya-ai-creative/skills/terakoya-web-design/SKILL.md` を参照する。ただし固定版の見た目を参加者ごとに再設計しない。
2. 本人だけが閲覧・編集できる新しい Work サイトを作る。既存の参加者サイトを上書きしない。表示名は「寺子屋AI マイサイト」。テスト用・試験版などの語を足さない。
3. 固定画面に、Work のサーバー側本人認証と永続保存を接続する。ローカル版の `localStorage` は制作時の動作見本であり、本人専用サイトの本番保存として使わない。画面を変えるための再生成はしない。
4. 保存対象は、事業プロフィール、ツール一覧と順序、アイコン、個人ロゴ、サイト名、テーマと配色。サーバー側で作成者本人を特定し、画面・データ取得/更新・画像取得の全経路で同じ本人確認を行う。最初にアクセスした人やログイン済み全員を管理者にしない。所有者が確定できない場合だけ、その一点を質問する。本人データを GitHub や公開ファイルへ書かない。
5. 告知は `docs/announcements.md` に従い、サイトの `/api/announcements` から固定した公開 `announcements.json` だけを取得する。ブラウザから任意 URL を中継できる API にしない。`isDemo:true`、期限外、不正 URL の告知は出さない。読み込み失敗でも本人の編集を止めない。既存の共通告知データを勝手に書き換えない。
6. デスクトップ幅と390px幅で表示し、プロフィール保存→再読込、ツール追加/編集/並べ替え/解除、URL検証、コピー、テーマ、本人以外のアクセス拒否、告知の期限とデモ除外を確認する。確認できない点は未確認と書く。

## 制作中の聞き取り

サイト制作は回答待ちで停止しない。非同期に回答を受け取れる場合だけ、事業名と「誰に何を提供しているか」を一問ずつ聞く。既知なら再質問しない。回答がないままでも空のサイトを完成させる。価格、実績、URLなどを創作しない。回答があれば同じサイトの初期プロフィールへ一度だけ反映し、後から本人が編集した内容を再デプロイで戻さない。

## 完成条件と境界

- 本人限定で開けるサイト URL を返す。ZIPだけ、コードの説明だけ、作成したつもりの報告で終えない。一般公開、共有設定、外部送信は行わない。
- 参加者に CLI、Git、APIキー、手動デプロイ、ZIP解凍を求めない。追加確認が不要な作業は進める。
- Work が固定ファイル取得、本人認証、サーバー保存、非公開発行のいずれかを提供できない場合、その機能を実現したと偽らない。未完了の理由と代替手段だけを簡潔に伝える。
- 最後に、URL、適用版、保存と本人限定アクセスの確認結果、未確認点を短く返す。

この固定版の `app.js` はローカル表示用に `localStorage` と GitHub raw JSON を使う。Work 本番では本人認証済みサーバー保存と同一オリジン告知 API に差し替える必要がある。差し替えができない場合、本人限定の完成サイトとは呼ばない。
