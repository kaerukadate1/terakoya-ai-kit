# 作り込む前に確かめる小さな実験

## 適用する仕事
試したいアイデア・使える時間と予算・すでにある発信先やつながりを用いて、作り込む前に確かめる小さな実験を行う。使う枠組みはリーン／仮説検証。枠組みを埋めて終わらず、結論と次の一手まで出す。

## 入力
試したいアイデア・使える時間と予算・すでにある発信先やつながり

## 進め方
1. アイデアが成り立つために正しくないと困る前提を書き出し、一番あやしいものを1つ選ぶ。
2. その前提を、作り込まずに1週間で確かめる方法を考える（告知だけ先に出す、数人に聞く など）。
3. 7日間の動きと、続ける・見直す・やめるを決める目安を先に置く。
4. 結果をどう記録するかと、次に頼む担当を出す。

## 成果物の型
7日間の検証案と、見直しの条件。図解の「作戦ボード」としてまとめ、ほかの担当も読む「事業メモ」を更新する。

## 品質チェック
- 売上や申込数を予測として約束しない。見る目安として置く
- 結論の言い切り方を根拠の強さにそろえる。需要や効果を確認できていないときは「〜の可能性がある」「〜と見立てる」と書く
- 競合が少ないことを需要の証明にしない
- 顧客像・価格・成果を推測で断定せず「確認」と「推測」を分ける
- 施策を並べすぎず、一人で今週できる一手に絞る

## この手順について
寺子屋AIオリジナル。リーン／仮説検証という定番の考え方を、一人で事業をする人向けに組み直したもの。外部のスクリプトやコネクタは使わない。
