# AIアシスタント設計ツール

寺子屋AI 第4回「自分だけのAIアシスタントを作ろう」。v0.4.1。

上部ツールバー・工程ナビ・入力/編集面・設定確認パネルの作業用UI。青緑と金の配色を使い、選択中・主操作・補助操作・ダウンロードを区別します。見た目はapp/tool-ui.cssをstyles.cssの後に読み込みます。保存形式と機能はv0.3.0のまま維持します。

事業・プロジェクトの準備なしで、汎用のアシスタントを先に作って保管します。特定の事業の専属設定ではありません。

## 設計するもの

1. 5カテゴリーから各6担当、合計30担当。カスタム役割は設けません。
2. 名前、話し方10種類、判断方針8種類、任せる範囲3種類、相談タイミング3種類。
3. 見た目: 表現5、モチーフ5、雰囲気6、世界観・デザイン6。メインとアクセント各64色、自由色も選べます。服装は強制しません。
4. プロフィール、画像、Markdown設定、短い呼び出し文を一つのパッケージとして保存。
5. 一覧で検索・再編集・複製・一覧からの削除・JSONバックアップ・追加読み込み。

設定組み合わせ: 21,600通り。見た目の指定組み合わせ: 3,686,400通り。合計79,626,240,000通り。能力数や異なる生成画像の保証数ではありません。自由色は計算外です。

## 持ち込んで使う

04の目立つ「設定ファイルをChatGPTへ」からMarkdownを保存し、プロジェクト内の新しいチャット、またはWorkへ添付して、頼みたい仕事を一緒に送ります。別の長い呼び出し文をコピーするのは通常不要です。添付しただけでプロジェクト指示へ自動登録・全チャット適用される保証はありません。設定が反映されないときだけ、折りたたみ内の短い起動文を使います。プロジェクト作成は必須ではありません。

## 担当ごとの専門手順

04のプロフィール画像と設定ファイルの間に「使用スキル」を表示。原典スキル名と、この担当での使い方を確認できます。表示文はskill-display.json、配信用データはapp/role-skills.jsから生成します。

30担当すべてに専用の手順・成果物の型・品質チェックを組み込みます。公開GitHubの28原典を30担当向けに日本語化・再構成した翻案です。同じ原典を別の仕事へ応用する担当もあります。「30個の別々の上流スキル」や「外部ツールのインストール」ではありません。

- [担当と原典の対応](role-catalog.json) / [取得元とSHA-256](skills/roles/sources.lock.json)
- 原典: [Corey Haines / marketingskills](https://github.com/coreyhaines31/marketingskills)、[Alireza Rezvani / claude-skills](https://github.com/alirezarezvani/claude-skills)、[SkillMedev / skills](https://github.com/SkillMedev/skills)、[Doculent / community](https://github.com/doculent/community)。4リポジトリともMIT。固定コミット、原文、許諾表示をskills/roles/とskills/licenses/に保存。
- ダウンロードするMarkdownは選んだ担当の専門手順と許諾表示を含み、利用時のGitHub再取得は不要。原典のスクリプト・API・外部コネクタは実行も導入もしません。
- 再生成: `node character-studio/scripts/build-role-skills.cjs`。検証: 同コマンドに`--check`。原典の再取得は明示的に`--fetch`を指定する時だけ。

役割は呼び出したチャットだけに適用します。全チャットへの一律適用、独立エージェント登録、別事業間の記憶同期、常駐・定期実行は含みません。送信・公開・購入等の承認境界はすべての設定で共通です。

## 画像制作

03は見た目の設定のみ。04の「パッケージを制作」でChatGPT Workを開き、画像生成と同じSiteへの返送を依頼します。ツールは15秒ごとと復帰時に結果を照合し、画像を取り込みます。「保存して一覧へ」で保管します。設定本文は画面に出しません。呼び出し文は添付・プロジェクト資料共通の1種類です。

返送にはWorkが同じSiteのsourceを編集・配信できる必要があります。第2回のcompleted-imagesファイル方式、第3回のreturns方式と同じく、ファイルと結果JSONを読み込む方式です。自動経路では画面操作・カーソル・アップロードダイアログを使いません。非対応なら画面操作へ迂回せず、失敗理由と完成画像を返し、利用者が常時表示の手動追加を使います。60分で自動確認を止め、手動再確認・待ちの解除ができます。別の依頼や変更前の見た目の画像は自動適用しません。顔写真の推測や既存人物・キャラクターの模倣は行いません。

再読込直後・画面復帰時・15秒間隔で確認します。完了JSONがまだなくても、同じ依頼IDのフォルダにPNGが保存されていれば画像自体を確認して受け取れます。不一致の完了JSONを無視して画像だけ取り込むことはしません。通信エラー時は待機情報を保持して再試行します。

04の「画像を手動でアップロード」は常時表示。ChatGPTの完成画像を保存して選択できます（PNG・JPEG・WebP、20MBまで）。画像の読み込みと保存が成功してから返送待ちを解除します。失敗時は元画像と待機情報を維持します。依頼時の設定へ戻す確認付きボタンも用意しています。

## 保存

ブラウザのlocalStorageに保存。端末・ブラウザ・URLをまたぐ自動同期はありません。一覧は初期状態で空、画像は任意。保存失敗は未保存として表示し、パッケージJSONへ退避できます。Markdownや呼び出し文は保存レコードから一括生成します。

v0.1のデータは読み込み時に旧形式の原本を別キーへ残し、旧事業情報・自由記述を保管欄に保持します。旧情報を汎用Markdownへ自動で混ぜません。カスタム役割等は既定選択肢へ対応付けるため、本人に確認を促します。

公式参照: [Projects](https://learn.chatgpt.com/docs/projects)、[Work](https://learn.chatgpt.com/docs/web)。各受講生の環境での生成・呼び出し成功は別途検証が必要です。
