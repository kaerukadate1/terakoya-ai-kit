# 開発と検証

正本はcharacter-studio/app/。リリースはnode scripts/generate-tool-release.cjs character-studio --writeで生成する。

- node --test character-studio/tests/core.test.cjs
- node scripts/generate-tool-release.cjs character-studio --check
- node scripts/verify-entrypoints.cjs
- node character-studio/scripts/serve.cjs（既定8834）

ブラウザで6カテゴリーと各6担当、仕事を頼む（依頼文・作戦ボードの返送と貼り付け・引き継ぎ・深掘り・次の一手のチェック・作戦室）、10/8/3/3選択、64色ずつ、名前だけでの保存、画像取り込み、Markdownダウンロード、呼び出し文コピー、再読込、複製、検索、削除確認、バックアップ追加を確認する。PC・モバイル幅で文字切れ・はみ出しを確認する。

旧localStorageキーは保持し、v1移行では原本をterakoya-character-studio-v1-before-v2に残す。壊れた既存データは上書きせず自動保存を停止する。課金APIや同期バックエンドは追加しない。

保存対象はプロフィール・画像・Markdown生成元・呼び出し文生成元を持つ一つの設定レコード。旧事業の情報はバックアップ内に保管し、通常画面には出さない。03は設定だけ、04の制作ボタンでChatGPTへ渡す。bridge.jsは依頼ID・設定ID・見た目キー・originを検証し、Workが同じSiteへ保存・配信したPNGを取り込む。依頼状態は別localStorageキー。保存済み一覧は利用者の保存操作まで更新しない。Work側の編集・配信権限がなければ手動画像追加が代替。

## v0.5.0 で増えたファイル

- app/strategy.js: 「事業の作戦」6担当の、作戦ボードの図の形・依頼の例・引き継ぎ先。専門手順は role-catalog.json にあり、ほかの担当と同じく build-role-skills.cjs が生成する。
- app/board.js: 作戦ボードの検証・描画・返送の照合。app/board-samples.js は見本（架空の事業）。
- tests/board.test.cjs: 作戦ボードのテスト。
- build-role-skills.cjs は36担当すべてを扱う。原典は34件。
- 読み込み順: role-skills.js → strategy.js → core.js → bridge.js → board.js → board-samples.js → app.js。
- 担当や選択肢の数を変えたら、index.html の「約○億通り」と担当数の表示、README・BUILD_PROMPT の数値を直す。
