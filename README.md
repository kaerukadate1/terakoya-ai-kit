# 寺子屋AI 制作キット

ChatGPT WorkとSitesで、本人専用の制作ツールと、事業を伝えるLP・告知画像を作るキットです。参加者は短い開始文をWorkへ送り、AIがGitHubの制作指示と固定ファイルを読みます。その後、本人の素材を使って成果物を仕上げます。

## 目的に合わせて入口を選ぶ

| 作りたいもの | 最初にWorkへ渡すもの | できあがるもの |
| --- | --- | --- |
| LP（現行の実践稽古の入口） | [LP版の開始文](releases/lp-maker-pilot-20260925/START_HERE.txt) | 本人専用LP制作ツール、3案の比較、選択した1〜3案の完成LP |
| チラシ・SNS告知画像 | [画像版のスターター](releases/workshop2-image-v1/STARTER_PROMPT.txt) | 本人専用画像制作ツール、媒体ごとに仕上げた画像 |
| 制作ツール・資料の仕事場 | [マイサイトv5のスターター](releases/mytools-v5/STARTER_PROMPT.txt) | Webツール、ファイル、スキル、プロンプト等を登録する本人用マイサイト |
| 告知文8種類とLP・画像（初版） | [01 マイツール開始文](prompts/01-start-mytools.txt) | マイツール＋告知ツール。初版の順番は下の折りたたみ参照 |

これらは別の制作経路です。LP版はマイツール作成を前提にしません。開始文や仕様を全部まとめて渡さず、目的に合う入口を1つ選んでください。`docs/` の制作手順・検証記録は主に初版向けです。現行の各ツールは `releases/` 内の制作指示を使います。

## LPを作る：読み込ませる順番

| 順番 | 本人がすること | AIが読むもの・完成の目印 |
| --- | --- | --- |
| 1 | [START_HERE.txt](releases/lp-maker-pilot-20260925/START_HERE.txt)の2行をまとめてWorkへ貼り、送信 | [WORKSHOP_PROMPT.md](releases/lp-maker-pilot-20260925/WORKSHOP_PROMPT.md)を読む |
| 2 | 作成された本人用URLを開く | 実行8ファイル＋制作ルール6ファイルを取得し、新しい本人限定サイトへ保存・非公開発行する |
| 3 | 商品・セミナー名、対象者、悩み、提供内容、持ち帰れること、確定した開催・申込情報を入力 | 本人の制作素材がそろう。迷ったら「ChatGPTに相談」を使う |
| 4 | 掲載項目と文章を調整し、9方向から3つのデザインを選ぶ | ツール内で3案を比較できる。この比較は固定ロジックのHTML初稿 |
| 5 | Workで仕上げる1〜3案を選び、ツールが用意した依頼文をWorkへ送信。使用する写真は別途添付 | 入力JSONと同梱スキルを使い、文章・デザイン・画像を整えて実際のLPを仕上げる |
| 6 | 完成LPを開き、制作一覧・設定編集・再訪を確認 | 同じ本人サイトへ完成物と制作設定を保存・再発行できたことを確認する |

初回は1案を仕上げ、URLを保存して再び開けるところまでを目標にします。完成LPの一般公開やSNS投稿は別の操作です。

AIが取得する実行ファイルは `index.html`、`styles.css`、`overrides.css`、`core.js`、`library.js`、`app.js`、`completed-lps.json`、`history.json` の8個です。制作ルールは `skills/` 内のコピーライティング・Webデザイン・レビューの3スキルと各参照資料の計6個です。参加者によるプラグイン導入やGitHub操作は前提にしません。

写真は制作依頼のJSONに含まれません。ツールで写真を選んだ場合も、Workで使う写真は別添付してください。画像生成が使えない場合は画像なしの到達点と未生成の箇所を分けます。

## 「ChatGPTに相談」の使い方

基本は空欄から、本人のWorkが参照できる過去チャット・同じプロジェクトの資料・メモリを使って、本人の事業や検討中のアイデアの入力案を作ります。サイトが本人の全チャット履歴を直接取得する機能ではありません。

LP版とチラシ・SNS画像版では、サンプルのまま残っている値を相談文から除外し、相談開始時に入力欄からも除きます。本人が書き換えた項目は保持します。相談結果は返答リンクまたはJSONで反映し、通常は空欄だけを埋めます。以前の相談回答欄と上書きチェックは相談開始時にリセットします。

根拠が見つからない項目は空欄にし、日時・価格・実績・口コミ・申込先を創作しません。参照できる事業情報がなければ、サンプルで穴埋めせず空の入力案を返す指示です。対象事業が複数あれば混ぜずに確認します。

## 初版の手順

各STEPは「やること → 使うもの → 終わった目安」の順です。つまずいたら[トラブル対処](docs/troubleshooting.md)を見てください。

### STEP 1　準備する

- やること：ChatGPTのワークで、Sitesを使える状態にします。
- 終わった目安：新しいワークで `@Sites` の指示を送れる。

### STEP 2　マイツールを作る

- やること：ワークに [01-start-mytools.txt](prompts/01-start-mytools.txt) を貼り付けます。制作が始まったら、事業名と事業内容を聞かれるので答えます。
- 使うもの：`prompts/01-start-mytools.txt`
- つまずいたら：AIが仕様を読めない場合は [02-mytools-full.txt](prompts/02-mytools-full.txt) と [共通告知仕様](docs/announcements.md) をそのまま貼って渡します。
- 終わった目安：3画面（マイツール・事業プロフィール・設定）のサイトがバージョン保存されている。

### STEP 3　セミナーまるっと用意くんを作って登録する

- やること：ワークに [03-start-seminar.txt](prompts/03-start-seminar.txt) を貼り付け、できたツールを[マイツールへ登録](docs/registration.md)します。
- 使うもの：`prompts/03-start-seminar.txt`
- 終わった目安：マイツールの一覧に「セミナーまるっと用意くん」のカードがあり、「開く」で起動できる。


### STEP 4　告知文を作る

- やること：ツールに告知素材と事業情報を入れ、媒体を選び、「ChatGPTで開く」で依頼を送り、返ってきたJSONを取り込みます。
- 使うもの：セミナーまるっと用意くん（操作の詳細は[制作手順](docs/production-flow.md)）
- 終わった目安：選んだ媒体の文章がツールに保存され、再読み込みしても残っている。

### STEP 5　告知LPを作る

- やること：保存したLP原稿をもとに、ワークへ [04-create-lp.txt](prompts/04-create-lp.txt) を貼って実際のLPを作り、確認用URLをツールへ記録します。
- 使うもの：`prompts/04-create-lp.txt`
- 終わった目安：PC・スマートフォンで表示したLPのURLが、ツールの結果に関連付いている。

### STEP 6　チラシ・SNS画像を作る

- やること：保存した原稿をもとに、ワークへ [05-create-images.txt](prompts/05-create-images.txt) を貼って画像を生成し、ツールへアップロードします。
- 使うもの：`prompts/05-create-images.txt`
- 終わった目安：文字の誤りや切れのない画像ファイルが、ツールの結果に関連付いている。

このキットを参照しただけで、サイトの作成・公開やSNS投稿が完了するわけではありません。作成されたサイトと保存状態を確認して利用を始めてください。

## 初版でできあがるもの

- 本人専用のマイツール：事業プロフィールとツール一覧。
- 本人専用のセミナーまるっと用意くん：素材を整理し、ChatGPTへ渡す指示を作り、返ってきた結果を保存。過去の告知と依頼は履歴として残る。
- お客様向けの告知LPと、チラシ・SNSに使う画像。
- マイツール左下に表示する、寺子屋AIの共通告知。

本人専用の情報は公開リポジトリへ入れません。公開LPには掲載を決めた情報だけを使います。

## 検証範囲と残件

- LP版の既存テストとサンプル除外の回帰テストは `node --test releases/lp-maker-pilot-20260925/tests/*.test.cjs` で確認できます。画像版は `node --test releases/workshop2-image-v1/tests/*.test.cjs` と `node releases/workshop2-image-v1/tests/smoke.cjs` を実行します。
- 自動テストの成功と、本人のWorkでのファイル取得・認証・非公開発行・画像生成・完成物一覧への反映は別の確認です。配布前に参加者と同じ条件で通してください。
- LP版の制作中履歴には既知の形式不整合があります。`history.json` は `{ "entries": [] }` 形式ですが、読み込み先の `normalizeHistory` は配列のみを受け取ります。別端末での制作中履歴の復元は修正・実機検証が必要です。
- [初版の実測結果](docs/validation-results.md)は2026-09-13の運営者Proでの結果です。最新LP版・画像版・告知V3や、全参加者プランの動作保証ではありません。
- 本人の入力・写真・保存データを公開GitHubへ書き戻しません。既存の本人サイトはGitHub更新だけでは自動更新されません。今回の変更を既存サイトへ適用するには、そのサイト側の修正・確認・保存が必要です。

## 配布する版を固定する

検証した版を配布するときは、開始文のURLだけでなく、制作指示の内部にある取得先も同じタグまたはコミットへ固定します。入口だけ固定して内部が `main` のままなら、全ファイルの版は固定されません。確認できた操作と未確認点は、実施日・対象版・利用条件を分けて記録してください。
